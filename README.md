# 🛒 Online Shop Analytics: генератор данных

Учебный проект: генератор **реалистичного потока заказов интернет-магазина** для последующей потоковой аналитики (хранение → анализ → визуализация).

*Модуль генерации данных: первый компонент платформы.*

---

## 📖 О проекте

Генератор создает поток заказов интернет-магазина и записывает их батчами в хранилище. Данные учитывают время суток, день недели и сезон, а также содержат редкие аномальные заказы, которые затем можно искать в аналитике.

Структура проекта повторяет архитектуру учебного примера (`RealTime-AnalyticsPlatform`), но предметная область другая: вместо показаний метеостанций генерируются заказы.

### ✨ Возможности модуля генерации

- 🎯 **Реалистичные заказы**: товар, клиент, количество, сумма, способ оплаты, статус.
- 🌗 **Сезонность**: суточный (пик во второй половине дня), недельный (в выходные заказов больше) и годовой (рост перед Новым годом) циклы плюс случайный шум.
- ⚡ **Аномалии**: редкие выбросы (оптовый заказ, необычно дорогой заказ, ошибка цены, ночной заказ) помечаются флагом `is_anomaly`.
- 🚀 **Батчевая запись**: пачками, а не по одной строке.
- 🔁 **Устойчивость к отказам**: retry с экспоненциальным backoff.
- 🧪 **Детерминизм**: при одинаковом `seed` генерируются одинаковые данные.

## 🏗 Архитектура

Ядро домена не зависит ни от конкретной БД, ни от способа генерации.

| Слой | Файл | Ответственность |
|------|------|-----------------|
| 🧩 Домен | `models.py` | `Product`, `Customer`, `Order` и перечисления: чистые модели без знания о БД |
| ⚙️ Генерация | `generation/` | сезонность, самплеры полей заказа, аномалии, справочники |
| 🔁 Повторы | `retry.py` | экспоненциальный backoff при отказах хранилища |
| ⚙️ Конфигурация | `config.py` | настройки генератора |

### Применяемые принципы

- **Strategy**: каждое поле заказа (товар, количество, способ оплаты, статус) выбирается отдельным самплером с единым контрактом. Новое поле означает один новый класс.
- **Чистые функции**: сезонность зависит только от момента времени, поэтому легко тестируется на фиксированных датах.
- **Разделение слоев**: модели, генерация, повторы и настройки лежат в отдельных модулях.

## 📊 Данные

**`products`** (справочник):

| Поле | Тип | Описание |
|------|-----|----------|
| `product_id` | int | идентификатор товара |
| `name` | str | название |
| `category` | enum | категория: `electronics / clothing / books / home` |
| `price` | float | цена за единицу |

**`customers`** (справочник):

| Поле | Тип | Описание |
|------|-----|----------|
| `customer_id` | int | идентификатор клиента |
| `name` | str | имя |
| `city` | str | город |

**`orders`** (события):

| Поле | Тип | Роль |
|------|-----|------|
| `order_id` | int | идентификатор заказа |
| `timestamp` | datetime | момент заказа |
| `customer_id` | int | связь со справочником клиентов |
| `product_id` | int | связь со справочником товаров |
| `quantity` | int | метрика |
| `total_amount` | float | метрика (цена × количество) |
| `payment_method` | enum | размерность: `card / cash / sbp` |
| `status` | enum | размерность: `created / paid / shipped / delivered / cancelled` |
| `is_anomaly` | bool | флаг выброса для анализа |

## 🌗 Сезонность

Итоговая интенсивность заказов равна произведению трех коэффициентов (см. `generation/seasonality.py`):

| Цикл | Пик | Минимум | Диапазон |
|------|-----|---------|----------|
| Суточный | около 17:00 | около 05:00 | 0.5 - 1.5 |
| Недельный | выходные | середина недели | 0.85 - 1.15 |
| Годовой | середина декабря | середина лета | 0.8 - 1.2 |

---

## ⚡ Аномалии

С небольшой вероятностью обычный заказ превращается в аномальный и получает `is_anomaly = True`:

| Тип | Что меняется |
|-----|--------------|
| `bulk_order` | оптовое количество вместо 1-2 штук |
| `high_value_order` | сумма заказа в разы выше обычной |
| `price_error` | сумма почти нулевая |
| `night_order` | заказ в неурочное время |

> Флаг `is_anomaly` является учебным упрощением: в реальной системе аномалии определяются аналитикой по данным, а не приходят готовыми. Здесь он служит «меткой истины» для проверки результатов анализа.
